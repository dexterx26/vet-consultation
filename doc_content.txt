Veterinary Teleconsultation App — System Requirements
1. Project Overview
The system is a web-based veterinary teleconsultation platform that connects pet owners/clients with licensed veterinarians for remote consultations through chat and video calls.
The platform will have three main user types:
Client / Pet Owner 
Veterinarian 
Administrator 
Development Approach
Phase 1: Web ApplicationPhase 2: Mobile Application — Android/iOS using the same backend/API
The system should be designed from the beginning with an API-first/backend architecture so the mobile application can reuse the existing authentication, user, pet, veterinarian, booking, chat, and consultation services.

5. Veterinarian Search
When a client needs a consultation, they can search for available veterinarians.
Search/Filter Options
Clients can filter veterinarians by:
Distance/location 
Animal type 
Breed expertise 
Area of specialization 
Availability 
Consultation fee 
Language 
Online status 
Location-Based Suggestions
The system should prioritize veterinarians based on the client's location.
Example:
Client location: Quezon City
The system may display:
Veterinarian 1 — 2.5 km away 
Veterinarian 2 — 4.1 km away 
Veterinarian 3 — 6.8 km away 
The system should not require the veterinarian and client to be in the same location. Location is primarily used for proximity-based suggestions.
For privacy, the platform should avoid exposing a veterinarian's exact personal address to clients unless the veterinarian explicitly provides a clinic location.

9. Communication
Communication should only become available after the veterinarian accepts the consultation.
9.1 Chat
Client and veterinarian can communicate through an in-app chat.
Features:
Text messages 
Image attachments 
File attachments 
Message timestamps 
Read/unread status 
Online/offline status 
Notifications 
Consultation-specific chat history 
The chat should be associated with the specific consultation.
Example:
Consultation #10025
    ├── Client
    ├── Veterinarian
    ├── Pet
    └── Chat History
This prevents unrelated conversations from being mixed together.
10. Video Consultation
After the consultation is accepted and reaches its scheduled time, the client and veterinarian can start a video consultation.
Video Features
Start video call 
End video call 
Microphone on/off 
Camera on/off 
Connection status 
Optional screen sharing 
Optional image/file sharing 
Call duration 
The video call should only be accessible to the client and veterinarian assigned to that consultation.
Recommended Architecture
The application should use a video communication service/API rather than building the entire video infrastructure from scratch.
The backend should generate/authorize the consultation session and provide secure access to the video room.

19. Location System
The location system should store enough information to support proximity searching.
For example:
country
province
city
municipality
latitude
longitude
The system can calculate approximate distance between client and veterinarian.
Example:
Client
14.6760, 121.0437
Veterinarian A
14.6500, 121.0500
Distance: ~3.0 km
The search results can then be ordered by distance.
Important: location matching should be based on coordinates or standardized geographic data rather than simply comparing text such as "Quezon City".
